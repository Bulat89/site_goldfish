# Goldfish — сайт

Сайт Goldfish — команды AI-агентов для гостевых домов, мини-отелей и апартаментов. Шесть
агентов-сотрудников («Каналы продаж», «Цены и загрузка», «Гости», «Репутация», «Прямые продажи» и
«Управляющий») сверяют площадки, отвечают гостям, следят за отзывами и рекламой, а владельцу
приходят сводка и согласования в Telegram. Сайт — лендинг, вход через Яндекс ID и **личный кабинет**
владельца: всё, что он делает, — в одном месте и в одном экземпляре. «Сегодня» (первые шаги,
решения, показатели), «Агенты» (команда, права, режим работы), «Объект» (эталон, объявления,
конкуренты), «Цены» и «Настройки» (расширение, CRM, мессенджеры, аккаунт). Позже через этот сайт
будут оформляться подписки; сейчас доступ есть у каждого, кто вошёл.

| Гость                        | Первые шаги в кабинете       | Агенты                     | Цены                     |
| ---------------------------- | ---------------------------- | -------------------------- | ------------------------ |
| ![Лендинг](docs/landing.png) | ![Кабинет](docs/cabinet.png) | ![Агенты](docs/agents.png) | ![Цены](docs/prices.png) |

## Как это устроено

```
Пользователь ──► Сайт (этот репозиторий) ──── API оператора ────► Сервер Goldfish
   │  вход через Яндекс ID                    пользователь, токен
   │  скачивает zip, получает ключ подключения
   │
   └──► Расширение ──── WebSocket /ws + токен из ключа ────► Сервер Goldfish
```

### Личный кабинет

После входа `/` ведёт в кабинет `/cabinet`. Каждый раздел — страница со своим адресом и общим верхом:
название объекта и вкладки (у «Сегодня» — число решений, которые ждут владельца). Страница просит у
сервера Goldfish только то, что показывает.

| Вкладка     | Адрес               | Что в ней                                                                                         |
| ----------- | ------------------- | ------------------------------------------------------------------------------------------------- |
| «Сегодня»   | `/cabinet`          | «Первые шаги», изучение, очередь согласований, показатели, сообщения управляющего                 |
| «Агенты»    | `/cabinet/agents`   | режим работы (волны, уровень автономности, пауза), агенты и права их обязанностей, режим площадок |
| «Объект»    | `/cabinet/property` | эталон объекта, объявления на площадках, конкуренты                                               |
| «Цены»      | `/cabinet/prices`   | цены прямых конкурентов, рекомендация, графики, доказательства                                    |
| «Настройки» | `/cabinet/settings` | расширение и ключ подключения, CRM, мессенджеры, сводка и тихие часы, вебхуки, аккаунт            |

Что меняет работу всех агентов сразу — идущее изучение и пауза — каждая страница говорит строкой под
вкладками; где у этого есть своя карточка («Сегодня» — изучение, «Агенты» — пауза), строки нет.
Старые адреса (`/start`, `/agents?tab=…`, `/agents/prices`) ведут в нужное место кабинета.

**Одна вещь — одно место.** Не заводите второй способ ввести то, что уже вводится:

| Что                                                 | Где                                                                                                                                     |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Скачать расширение, ключ подключения, подключено ли | «Настройки» → «Расширение для браузера»                                                                                                 |
| Кабинет CRM                                         | «Настройки» → «Кабинет вашей CRM» (в редакторе систем эталона CRM нет)                                                                  |
| Привязка Telegram, MAX, WhatsApp, отвязка           | «Настройки» → «Мессенджеры»                                                                                                             |
| Время сводки, тихие часы, ответы на отзывы          | «Настройки» → «Сводка и уведомления»                                                                                                    |
| Ссылка на объявление на площадке                    | «Объект» → «Объявления на площадках»: поле у каждой площадки (в редакторе систем адреса объявления нет, кроме площадок для турагентств) |
| Список конкурентов                                  | «Объект» → «Конкуренты», рядом с поиском (в эталоне списка нет)                                                                         |
| Агенты, права, волны, автономность, пауза, площадки | «Агенты»                                                                                                                                |
| Решения, показатели, сообщения управляющего         | «Сегодня»                                                                                                                               |

#### Первые шаги

Пока что-то не сделано, вверху «Сегодня» — список «Первые шаги»: у каждого шага — что и зачем и
кнопка, которая ведёт туда, где это делается; первый невыполненный — главная кнопка. Отдельного
мастера нет: это один список на весь путь.

1. **Расширение** — «Настройки»: скачать, вставить ключ. Шаг отмечается, когда расширение хотя бы
   раз подключилось: `GET /api/extension` (по `GET /admin/users/<clientId>/<userId>` сервера
   Goldfish); пока оно не подключилось, карточка раз в 5 с спрашивает снова.
2. **Эталон** — название и номера. Проще всего по ссылке на объявление: у сохранённой ссылки есть
   кнопка «Заполнить эталон», пока эталон пуст.
3. **CRM** — «Настройки». Без CRM можно запускать агентов: после запуска шаг не спрашивается.
4. **Мессенджер** — «Настройки». Без сервера ботов и без Telegram-бота Goldfish шага нет.
5. **Запуск** — «Запустить изучение» (`POST /api/agents/launch`): сначала изучение (без
   подключённого расширения сервер откажет и ничего не изменится), затем вся команда, если ни один
   агент не был включён, и уровень автономности 3 «для начала», если стоит стартовый 4; владелец
   видит это в шаге заранее. Первые шаги пройдены (`users.onboarded_at`), когда изучение началось;
   пользователи, получившие токен до первых шагов, считаются прошедшими их (миграция 2).

Пока агенты не запущены и не включены, пульт (решения, показатели, сообщения) не показывается — он
был бы пуст; решение, которое уже ждёт, не скрывается никогда.

**Изучение.** Агенты открывают объявления и кабинет CRM, проходят по разделам и запоминают дорогу
(маршруты библиотеки сайтов). Пока оно идёт, сервер Goldfish запрещает любые изменения: правки
карточек, цены, ответы гостям не делаются и не предлагаются. Вверху «Сегодня» — карточка «Агенты
изучают ваши кабинеты» с ходом по каждой системе (страница спрашивает `GET /api/agents/study` раз в
15 с) и кнопкой «Закончить изучение — разрешить работу» (`POST /api/agents/study {on: false}`):
подтверждение называет, какие агенты будут работать и по какому уровню автономности. На остальных
вкладках — строка «Идёт изучение».

- Сайт хранит своих пользователей (Яндекс ID, имя, e-mail) и сессии в PostgreSQL.
- По кнопке «Получить ключ подключения» сайт через API оператора Goldfish заводит пользователя
  `yandex:<id Яндекса>` в клиенте «Сайт» и выпускает токен устройства; владелец получает его вместе
  с адресом сервера одной строкой — ключом подключения. Ключ показывается один раз, токен на сайте
  не хранится, только его id; новый ключ отзывает предыдущий. Когда расширение подключено,
  установка и ключ в «Настройках» свёрнуты.
- Расширение работает напрямую с сервером Goldfish: в работе агента сайт не участвует и может быть
  недоступен.
- Zip расширения сайт берёт у сервера Goldfish (`/extension/download`, он есть в его Docker-образе)
  или из своего файла `EXTENSION_ZIP`.
- Сайт читает и меняет агентов объекта через API оператора Goldfish от имени пользователя
  (`/admin/users/<clientId>/yandex:<id>/hotel/…`). Разделы кабинета:
  - «Сегодня» — «пульт управляющего» (`GET …/hotel/manager`): тот же, что во вкладке «Управляющий»
    расширения и в ботах, теми же словами. Пока страница открыта, `app.js` раз в 20 с спрашивает
    `/api/agents/today` и подменяет живую часть (согласования, показатели, сообщения), если пульт
    изменился: решение в Telegram или в расширении видно без перезагрузки. Решение на сайте уходит
    с `via: site` — остальные окна пишут «Согласовано на сайте»;
  - «Агенты» — режим работы (волны с подтверждением, что включится; уровень автономности
    управляющего от 1 до 4 с подтверждением, что он значит; пауза), агенты (переключатель у каждого,
    сводка прав его обязанностей, а в раскрытой карточке — права каждой обязанности кнопками «Сам /
    Правило / Согласование / Выкл», выше потолка обязанности кнопки неактивны, описание, расписание,
    читает она или меняет данные, и «Выполнить») и режим каждой подключённой площадки;
  - «Объект» — эталон объекта по разделам (основное, номера, системы и площадки, заезд и правила,
    ответы гостям, цены и допродажи) полями вместо JSON — то, чего форма не показывает (в том числе
    CRM и ссылки на объявления), сохраняется как было; заполнение «из карточки» (ссылка на
    карточку объекта на Авито, Яндекс Путешествиях и др. или её текст → черновик с найденными
    полями, которые владелец применяет галочками). **Объявления на площадках** — таблица: поле для
    ссылки у каждой площадки для гостей и у карт. Вставленная ссылка подключает площадку
    (`POST /api/agents/listings/links` → `…/hotel/listings/manual`: сервер проверяет, что ссылка —
    этой площадки), очищенное поле убирает объявление из эталона; рядом — что известно об
    объявлении: подключено, найдено при поиске (владелец отвечает «Моё / Не моё»), нет, не
    прочитано. Агент может искать объявления там, где адрес не известен, сверять карточки с
    эталоном и размещать объявление там, где его нет (каждое — по согласованию). **Конкуренты** —
    список (до 10: выбранные агентом и добавленные вручную; `POST /api/agents/competitors/list`
    меняет только его) и поиск: агент сам решает, кто прямой конкурент, и показывает причину,
    владелец может поправить;
  - «Цены» — прямые конкуренты, которых отобрал агент, средняя и медиана их цен, рекомендованная
    цена «от» с пересчётом по категориям и кнопкой «Принять» (меняет базовые цены в эталоне),
    графики — цена каждого конкурента с линиями медианы, средней и вашей цены, рынок по ночам и по
    датам сбора — и таблица доказательств: каждая цена с дословной цитатой со страницы, ссылкой и
    временем чтения. Данные — `GET …/hotel/prices` сервера Goldfish; графики рисует сервер сайта в
    SVG (без библиотек и inline-стилей — их запрещает CSP), подсказки при наведении — `app.js`, у
    каждого графика есть таблица;
  - «Настройки» — расширение и ключ; кабинет CRM (одна, «Нет CRM» — если брони ведутся вручную);
    мессенджеры (QR-коды и «Отвязать») или Telegram Goldfish; время сводки, тихие часы, лимит
    срочных и ответы на отзывы без согласования; токен вебхуков; аккаунт (имя, Яндекс ID, почта,
    доступ).

  Ответ на каждое изменение — сообщение внизу экрана. Изменения принимаются только со страниц самого
  сайта (проверка `Origin`) и только от вошедшего пользователя; отказы сервера (например, поднять
  права выше потолка обязанности) показываются как есть. Как устроены агенты —
  [docs/hotel-agents.md](https://github.com/Bulat89/goldfish/blob/main/docs/hotel-agents.md) в
  репозитории goldfish.

- Страница `/help` — инструкция пользователя по всем сценариям (открыта без входа): быстрый старт,
  поиск, вопросы по темам. У каждого ответа свой якорь (`/help#permission`); кабинет ссылается на них
  из тех мест, где нужно больше, чем сказано на странице, а инструкция — на места кабинета
  (`/cabinet/settings#connect`). Тест `test/help.test.ts` проверяет, что все такие ссылки ведут на
  существующие якоря.

- **Боты в Telegram, MAX и WhatsApp** — отдельный сервер
  [tg_goldfish](https://github.com/Bulat89/tg_goldfish). С `BOTS_URL` в «Настройках» → «Мессенджеры»
  появляется QR-код на каждый включённый мессенджер. Сайт просит у сервера ботов одноразовые коды
  (`POST /api/owners/<clientId>/yandex:<id>/codes`, токен `BOTS_API_TOKEN`) и рисует QR-коды сам — в
  SVG, без внешних картинок (библиотека `qrcode-generator`). Владелец сканирует код телефоном,
  мессенджер открывает бота, бот привязывает чат; дальше в нём согласования, агенты, поручения и
  задачи, сводка и срочное. Коды одноразовые и действуют час — их делают только при открытии
  «Настроек»; остальные страницы спрашивают лишь, какие чаты привязаны. Привязанные чаты видны там же
  и в «Первых шагах», в «Настройках» — «Отвязать». Без ответа сервера ботов страницы открываются без
  QR-кодов.

  Бот в каждом мессенджере один на всех владельцев — адрес в QR-коде у всех одинаковый,
  различается одноразовый код после `start=`: он привязывает чат к кабинету, в котором его
  показали. Чат служит одному владельцу: отсканированный во втором кабинете, он уходит из первого.

- **Владельцы не пересекаются.** Все пользователи сайта — пользователи одного клиента Goldfish
  («Сайт»), но у каждого свои объект, токен, браузер, задачи, чаты ботов и лимиты, а всё, чему
  агенты учатся в кабинетах владельца (личные записи библиотеки сайтов и номер его объекта в
  экстранете, траектории, черновики профилей, статистика сайтов), сервер Goldfish хранит по
  пользователю, а не по клиенту (`src/util/owner.ts` в репозитории goldfish). Расширение в одном
  профиле браузера закреплено за первым подключившимся владельцем: второй ключ в том же профиле
  сервер отклонит («этот браузер привязан к другому пользователю») — для второго аккаунта нужен
  другой профиль Chrome.

Код сервера и расширения — в репозитории [goldfish](https://github.com/Bulat89/goldfish).

## Подписки — куда подключать

Доступ решает одна функция — `accessOf(user)` в [`src/access.ts`](src/access.ts); сейчас она
пускает всех. Когда появятся тарифы:

1. Добавить в пользователя план и оплаченный период — новой миграцией в
   [`src/store/migrations.ts`](src/store/migrations.ts) (старые миграции не менять).
2. Считать доступ в `accessOf`: без доступа сайт не выдаёт ключ и не отдаёт zip, а на главной
   показывает причину.
3. При оплате и окончании периода отправлять состояние на сервер Goldfish:
   `POST /admin/users/<clientId>/yandex:<id>/subscription {"action":"activate"|"suspend","until":…}`.
   Сервер сам отключит расширение и остановит задачи, а после продления всё продолжится с того же
   места — диалоги и память сохраняются.

## Приложение Яндекс ID

1. Создайте приложение на [oauth.yandex.ru](https://oauth.yandex.ru/client/new), платформа —
   «Веб-сервисы».
2. Redirect URI: `https://<домен сайта>/auth/yandex/callback`. Для локального запуска добавьте
   `http://localhost:3000/auth/yandex/callback`.
3. Доступы: логин, имя и фамилия (`login:info`), адрес электронной почты (`login:email`), портрет
   (`login:avatar`).
4. ClientID → `YANDEX_CLIENT_ID`, Client secret → `YANDEX_CLIENT_SECRET`.

## Запуск локально

Нужен Node.js 22 и запущенный сервер Goldfish (его README, раздел «Быстрый старт»).

```bash
npm ci
PUBLIC_URL=http://localhost:3000 \
YANDEX_CLIENT_ID=… YANDEX_CLIENT_SECRET=… \
GOLDFISH_URL=http://localhost:8080 GOLDFISH_ADMIN_TOKEN=<ADMIN_TOKEN сервера Goldfish> \
npm run dev
```

Без `DATABASE_URL` пользователи и сессии живут в памяти и пропадают при перезапуске.

## Развёртывание в Timeweb Cloud

### Вариант А — App Platform, Docker Compose

1. App Platform → новое приложение из этого репозитория, тип «Docker Compose»
   (`docker-compose.yml` в корне). Сайт слушает порт `3000`, проверка состояния — `/healthz`.
2. В разделе переменных приложения задайте: `PUBLIC_URL`, `YANDEX_CLIENT_ID`,
   `YANDEX_CLIENT_SECRET`, `GOLDFISH_URL`, `GOLDFISH_ADMIN_TOKEN` (остальные — по желанию, список
   ниже). Compose подставляет их в контейнер сам — файл `.env` в репозитории не нужен и не должен
   там лежать.
3. База: без `DATABASE_URL` сайт использует PostgreSQL из того же compose. Надёжнее управляемая база
   Timeweb (резервные копии, переживает пересборку) — тогда задайте её строку в `DATABASE_URL`.
   Таблицы сайт создаёт сам при старте.
4. Привяжите домен. `PUBLIC_URL` — этот адрес с `https://`, он же в Redirect URI приложения Яндекс ID.

Если сайт не стартует, в логах приложения будет `Invalid configuration` со списком незаданных
переменных.

### Вариант Б — App Platform, Dockerfile

То же, но тип «Dockerfile» (порт `3000`, `/healthz`): контейнер только с сайтом, база — управляемая
PostgreSQL 16 в `DATABASE_URL` (обязательна), плюс `NODE_ENV=production`.

### Вариант В — облачный сервер с Docker

```bash
git clone https://github.com/Bulat89/site_ai_agent.git && cd site_ai_agent
cp .env.example .env     # заполнить: PUBLIC_URL, YANDEX_*, GOLDFISH_*, SITE_DOMAIN
docker compose -f docker-compose.yml -f deploy/caddy.yml up -d   # + Caddy с сертификатом Let's Encrypt
```

- A-запись домена (`SITE_DOMAIN`) — на IP сервера, порты 80 и 443 открыты. С Caddy сайт слушает
  только `127.0.0.1:3000`.
- Уже есть nginx или другой прокси с TLS — просто `docker compose up -d` и проксируйте на порт
  `3000`; закройте этот порт снаружи файрволом.
- Обновление: `git pull && docker compose up -d --build`.
- Резервная копия: `docker compose exec postgres pg_dump -U site site > site.sql`.

### Связь с сервером Goldfish

- `GOLDFISH_ADMIN_TOKEN` — это `ADMIN_TOKEN` сервера Goldfish, он даёт полный доступ к серверу:
  храните его как пароль. Если `/admin` закрыт от интернета (так советует документация Goldfish),
  разрешите адрес сайта или укажите внутренний адрес в `GOLDFISH_ADMIN_URL`.
- Пользователи сайта видны в панели оператора Goldfish (`/admin/ui`) в клиенте «Сайт» — с именем и
  e-mail. Лимиты и подписку пока можно менять там.
- Предупреждения и ошибки сайта (всё, что он пишет в лог с уровнем `warn` и выше, и падения
  процесса) сайт пачками отправляет в журнал ошибок сервера Goldfish (`POST /admin/errors`, тем же
  `GOLDFISH_ADMIN_TOKEN`). Там они лежат вместе с ошибками сервера и расширения, и их читает AI-
  ассистент через MCP-эндпоинт сервера — см.
  [docs/errors-mcp.md](https://github.com/Bulat89/goldfish/blob/main/docs/errors-mcp.md) в
  репозитории goldfish. Пока сервер недоступен, сайт держит до 200 последних ошибок и отправит их
  позже; выключается `REPORT_ERRORS=false`.
- `/extension/download` на сервере Goldfish открыт без входа. Чтобы zip был доступен только после
  регистрации, закройте этот путь на прокси Goldfish и положите zip на сайт (`EXTENSION_ZIP`).

## Переменные окружения

Сайт читает настройки из окружения (в docker compose — из `.env`, шаблон —
[`.env.example`](.env.example)). Пустое значение (`KEY=`) означает «не задано». Неверное значение
или недостающая обязательная переменная останавливают запуск с ошибкой. Адреса (`*_URL`) — только
`http://` или `https://`: они попадают в ссылки и перенаправления на странице.

В колонке «Обязательна»: **да** — без неё сайт не запустится; **да, если …** — обязательна при
условии; **нет** — есть значение по умолчанию или возможность просто выключена.

## Безопасность

- Вход — authorization code с PKCE и `state`. Токен Яндекса используется один раз, чтобы прочитать
  профиль, и не сохраняется.
- Cookie — `HttpOnly`, `SameSite=Lax`, по `https` с префиксом `__Host-` (поддомен не подложит свою
  сессию). Сессии хранятся в базе хешем.
- Изменяющие запросы (`/api/token`, `/api/agents/*`, `/logout`) принимаются только со страниц
  самого сайта (проверка `Origin`); CSP без inline-скриптов, страница не встраивается во фреймы.
- Персональные данные (имя, e-mail) хранятся в PostgreSQL — держите базу в России (152-ФЗ) и укажите
  `PRIVACY_URL`.
- Выдача токенов сериализуется в памяти процесса — запускайте одну реплику.
